# ADR-001. 조항 단위 청킹과 결정적 청크 ID

- 상태: 채택
- 날짜: 2026-09-08

## 맥락

약관·상품설명서는 조항이 의미 단위다. 고정 길이(예: 1,000자)로 자르면 "제7조 제2항의
통지 기한"이 두 청크에 걸쳐 반으로 갈리고, 검색은 앞부분만 찾아 답의 절반을 잃는다.

또 하나. 골든셋은 "이 질문의 정답이 이 청크에 있다"고 주장한다. 인제스천을 다시 돌릴
때마다 청크 ID 가 바뀌면 그 주장이 매번 무효가 된다.

## 결정

1. 조항 머리글(`제N조`, `제N조의M`)에서 자른다. 조항이 없는 문서는 통째로 한 블록.
2. 조항이 상한(1,200자)을 넘으면 문단 경계로 나누고 150자를 겹친다.
3. 청크 ID 는 `{doc_id}#{조항}#{seq}` 로 결정적으로 만든다. 해시나 순번을 쓰지 않는다.
4. **짧은 조항을 길이로 버리지 않는다.** 조항 블록의 하한은 12자, 조항이 없는 조각만 40자.

## 근거

4번은 실제로 데려온 교훈이다. 하한을 40자로 두었을 때 카카오뱅크 정기예금 특약의
제2조(예금과목)와 제4조(가입금액, 38자)가 통째로 사라졌다. 짧은 조항일수록 답이
명확해서 질문이 많이 나오는 조항이다.

상한 1,200자는 임베딩 모델의 입력 길이에서 왔다. arctic-embed-l-v2.0-ko 는 학습
최대 길이가 약 1,300토큰이라 그보다 긴 청크는 뒷부분이 벡터에 반영되지 않는다.

## 결과

- 코퍼스 49문서 → 3,700청크, 조항 청크가 대부분.
- 골든 인용 98건이 모두 청크 안에서 발견된다(`scripts/validate_golden.py`).
- 재실행해도 같은 ID 가 나온다(`tests/test_smoke.py::test_chunk_ids_are_deterministic_and_unique`).

## 대안

- **고정 길이 + 겹침**: 구현은 쉽지만 조항 경계를 무시한다. 조항번호형 질문(골든 8문항)에 불리.
- **의미 기반 분할(임베딩 유사도)**: 결정적이지 않아 청크 ID 가 흔들린다. 골든셋과 맞지 않는다.
