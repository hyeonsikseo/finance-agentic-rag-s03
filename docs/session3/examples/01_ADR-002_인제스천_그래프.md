# ADR-002. 인제스천에 LangGraph 를 쓰되, 문서당 LLM 루프는 두지 않는다

- 상태: 채택
- 날짜: 2026-09-08 (2026-09-28 게이트의 0장 규칙을 고치며 갱신)

## 맥락

문서 뭉치를 넣으면 어떤 것은 잘 읽히고, 어떤 것은 파서를 바꿔야 하고, 어떤 것은
스캔본이라 OCR 이 필요하고, 어떤 것은 형식 자체가 지원되지 않는다. 이 분기를
`if` 문으로 짜면 "어떤 문서가 어디로 갔는지"가 로그에만 남고 상태로 남지 않는다.

## 결정

**LangGraph 를 쓴다. 단, 제어흐름과 체크포인트 용도로만 쓴다.**

```
classify → parse → gate ─┬─ pass ───→ chunk → END
                         ├─ reparse → (pass | ocr | llm_repair)
                         ├─ ocr ────→ (chunk | dead_letter)
                         └─ fail ───→ dead_letter
```

- 노드 8개 중 LLM 을 쓰는 것은 `llm_repair` 하나뿐이고, 그것도 **다른 파서로 다시
  추출한 뒤에도 쓸 수 있는 페이지가 0장일 때만** 부른다.
- `thread_id = sha256(파일)`. 파일이 1바이트라도 바뀌면 다른 thread 가 된다.

## 근거

**LangGraph 는 스케줄러가 아니다.** 주기 실행·재시도·백필이 필요하면 Airflow·Prefect 가
맞다. 여기서 필요한 것은 "문서 하나가 조건에 따라 다른 경로로 가고, 그 경로가 상태로
남는 것"이라 LangGraph 가 맞다. 인제스천 리포트가 상태에서 그냥 나온다.

문서당 LLM 을 부르지 않는 이유는 셋이다. 비용이 문서 수에 비례해 늘고, 지연이 커지고,
무엇보다 **재현되지 않는다**. 같은 코퍼스를 두 번 넣었을 때 청크가 달라지면 골든셋의
gold chunk ID 가 무효가 된다.

## 체크포인터에 대해 알아 둘 것

LangGraph 의 체크포인터는 **중단된 실행을 이어서** 하는 장치다. 끝난 실행을 자동으로
건너뛰지 않는다. 같은 `thread_id` 로 다시 `invoke` 하면 처음부터 다시 돈다(실측: 8.16초 →
6.06초, 캐시 효과일 뿐 스킵이 아니다).

그래서 재실행 스킵은 파이프라인에서 직접 한다. `graph.get_state(cfg)` 로 완료된 상태가
있는지 보고 있으면 그 값을 그대로 쓴다. "체크포인터를 붙였으니 idempotent 하다"고
말하기 전에 실제로 재실행해 시간을 재 볼 것.

## 결과

- 51문서 중 48건 인덱싱, 3건 사람 검토 큐(HWP/HWPX 2건 + 띄어쓰기가 사라져 LLM 복구까지
  갔으나 키가 없어 건너뛴 1건).
- 게이트 판정: pass 40 / reparse 5 / ocr 4 / fail 2. LLM 복구 노드까지 간 문서 1건.
- 재실행 시 같은 결과.

## 되돌아본 실수

처음에는 게이트가 나쁜 페이지를 발견하면 **문서 전체를 사람 검토 큐로 보냈다.**
그 결과 492쪽짜리 실손 표준약관 정본이 2쪽 때문에 통째로 빠졌다. 부분 실패를 전체
폐기로 바꾸면 안 된다. 지금은 쓸 수 있는 페이지가 하나라도 있으면 인덱싱하고, 나쁜
페이지는 품질 표시만 남긴다.

두 번째 실수는 반대 방향이었다. 쓸 수 있는 페이지가 0장인 문서를 게이트에서 **바로
버렸다.** 그러면 LLM 복구 노드로 가는 문서가 한 건도 없어서 "실패 문서만 LLM 에 보낸다"는
원칙이 코드에서 확인되지 않았다. 지금은 깨진 페이지가 있으면 재추출 → LLM 복구 순으로
가고, 글자도 이미지도 없는 문서만 바로 버린다.
